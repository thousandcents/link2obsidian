# postprocess.py 扩展纪律（开发期陷阱）

扩展 `postprocess.py` 时（新增 `fix_*` 函数并接入 `process()` 流水线），
必须遵守以下纪律。本次在《CTA 因子动物园》实战中，因把技能真正跑在真实文件上，
暴露并修复了若干陷阱。

## 1. 幂等性是硬要求

`postprocess.py` 会被**反复执行**：每次文章入库 runner.py 自动调用一次，
且 Agent 常手动 `--dry-run` / 重跑复核。任何非幂等的 `fix_*` 都会造成
「每次都把同一处改一遍」的死循环，且 dry-run 永远报「有改动」，无法判断是否干净。

**已踩坑（已修复）**：`fix_heading_merged_with_body` 的 `——` 分支原实现：

```python
if "——" in body:
    idx = body.index("——")
    title_part = body[: idx + 2]   # 把 —— 留在标题里
    rest = body[idx + 2 :]
    return f"{prefix} {title_part}\n\n{rest}"
```

当 `——` 在行尾（标题自带破折号、无粘连正文，如 `### 4.1 ...管理员——`），
`rest` 为空，拆分前后这一行内容不变，但每次都返回「已拆分」→ 非幂等。

**修复模式**：

- 仅当 `——` 之后**确有正文**才拆分；且把 `——` 归入正文侧（标题只保留到 `——` 之前）：

```python
if "——" in body:
    idx = body.index("——")
    rest = body[idx + 2 :]
    if rest.strip():
        title_part = body[:idx]
        return f"{prefix} {title_part}\n\n——{rest}"
    return None   # —— 在行尾：无正文可分离，不拆，保证幂等
```

- 通用法则：任何「插入换行/分隔」的 fix，必须确保对**已处理过**的输入返回原样。
  写完新 fix 后，用真实文件跑两次（先写回、再 `--dry-run`），确认第二次报 0 改动。

## 2. 正则里的 `*` 必须转义

Markdown 加粗标记是 `**`，在 regex 字符类外 `*` 是量词。模式里写 `**：`
会触发 `multiple repeat` 错误（`**` 被当成「零或多 零或多」）。

- **错误**：`re.subn(r"(通俗版|通俗理解)**：", ...)` → `re.error: multiple repeat`
- **正确**：`re.subn(r"(通俗版|通俗理解)\*\*：", ...)`（`*` 转义为 `\*`）

## 3. 区分「孤儿加粗」与「合法加粗列表项」

把行首 `**- ` 直接替换成 `- ` 会破坏**合法**的加粗列表项 `**- 文本**`
（行内有闭合 `**`），结果变成 `- 文本**` 残留孤儿 `**`。

**正确模式**（负向先行断言：仅当整行不再出现另一个 `**` 时才改）：

```python
re.subn(r"(?m)^\*\*- (?=(?:(?!\*\*).)*$)", "- ", content)
```

- `**- 文本`（行内无闭合 `**`，真孤儿）→ `- 文本` ✓
- `**- 文本**`（合法加粗项）→ 不动 ✓

## 4. 表格：检测 + 告警，不要正则重建

被压平的表格（`<table>` 结构在 scraper 中被 `re.sub(r"<[^>]+>","")` 抹平，
单元格粘连成一行、用 `**` 分隔、丢失 `|`）**列边界是语义级的**，正则无法可靠
还原——硬重建只会错位。

**正确做法**：`detect_scrambled_tables()` 只**检测并告警**（不修改内容），
把静默失败转为显式 `⚠️ 需 AI` 提示，交给 Agent/LLM 按语义重建为 GFM pipe table。
检测签名：行内无 `|`、长度 > 40、含 ≥2 个 `%` 且存在 `**`。

**根因（未来可选根治）**：在 `SKILL.md` 内联 scraper 的 HTML→MD 阶段，
于 `content = re.sub(r"<[^>]+>", "", content)` 之前插入 `<table>` → GFM 转换，
可让未来文章从源头得到正确表格。改动面更大，需谨慎测试，未默认开启。

## 5. 验证清单（每次扩展后必做）

1. `python3 -m py_compile postprocess.py` — 语法编译
2. 构造含原始杂乱片段的临时 `.md`，`--dry-run -v` 跑，确认新规则按预期触发
3. 在**已处理过**的真实文件上跑两次，确认第二次幂等（0 实际改动）
4. 确认不误伤：合法加粗 `**- 文本**`、正常 `**关键词**` 行不被改动
