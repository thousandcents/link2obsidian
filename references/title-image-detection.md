# 图片全量视觉筛查与清理指南

> 本文档描述 link2obsidian 工作流中的**全量图片视觉筛查**流程。旧版「仅首图/题图识别」已升级为**对下载的全部图片逐一视觉分析**，详见 `SKILL.md` 第 4 步与 `references/wechat-image-triage.md`。

## 为什么是全量筛查

runner + postprocess 会把文章中所有 qpic.cn 图片无差别写入正文，包括封面图、引流二维码、装饰图、表情包、风险声明图等。这些非内容图会污染笔记库。因此必须对**每一张下载的图片**调用 `vision_analyze` 进行判定。

## 视觉分析提问模板

```python
vision_analyze(
    image_url,
    "请识别这张图片的类型：是封面图/题图、引流图、二维码、装饰图、表情包、风险说明，还是内容图（数据图表/架构图/流程图/示意图）？请详细描述图中内容。"
)
```

## 判定与处理矩阵

| 类别 | 处理 |
|------|------|
| 内容图（数据图表、架构图、流程图、示意图、软件截图、读者评论截图） | 保留 |
| 封面图（宽幅海报、品牌 logo、文章题图） | 删除引用 + 删除磁盘文件 |
| 引流图（带二维码的活动海报、私域转化图） | 删除引用 + 删除磁盘文件 |
| 二维码（纯二维码、社群/公众号引流码） | 删除引用 + 删除磁盘文件 |
| 装饰图（无信息量装饰、空白分隔符、纯色图） | 删除引用 + 删除磁盘文件 |
| 表情包（反应梗图、电影台词截图、情绪化表情包） | 删除引用 + 删除磁盘文件 |
| 风险说明（底部风险声明、投资提示、免责声明模板图） | 删除引用 + 删除磁盘文件 |
| 文末互动引导图（卡通人物+「求分享」「求点赞」等） | 删除引用 + 删除磁盘文件 |

**核心原则**：只有明确判定为「内容图」的才保留，其余 7 类一律删除。

## 稳健删除写法

```python
from pathlib import Path
import re

article_path = Path(".../Clippings/文章.md")
content = article_path.read_text(encoding="utf-8")

for img in ["xxxx.png", "yyyy.jpg"]:  # 待删图片列表
    content = content.replace(f"![{img}](Clippings/images/{img})", "")

# 清理多余空行
content = re.sub(r"\n{3,}", "\n\n", content)
article_path.write_text(content, encoding="utf-8")

# 删除磁盘文件
for img in ["xxxx.png", "yyyy.jpg"]:
    img_path = Path(".../Clippings/images") / img
    if img_path.exists():
        img_path.unlink()
```

⚠️ 不要用 `content.replace(img + "\n\n\n", "\n")` 这种依赖空白行数匹配的写法——`if img in content` 为真时，空白行数不匹配会导致 `replace` 静默无效，图片残留。

## 删除后的连带清理

- **悬空句**：删图后若紧邻一句只是该图的说明/引子（如「但我的表情仍旧 be like」），同样删掉，否则读起来断裂。
- **引流尾巴**：文末「------------分割线------------」+「周四直播…」+「扫码申请试听」+ 海报图，整体属于推广，按分割线截断删除。

## 旧版位置判定法（已废弃）

以下基于「首图位置」「引用次数」「alt 文本长度」的启发式规则已被**全量视觉筛查**取代，不再使用：

- ~~首图位于 frontmatter/摘要之后、正文之前~~
- ~~引用次数为 1 的专属图更可能是题图~~
- ~~alt 文本为空或仅为十六进制文件名~~
- ~~共享底图（被 30+ 文章引用）不应删除~~

这些规则在混合图片场景（如文中既有内容图又有表情包）下容易误判，已被 vision_analyze 的语义判定完全替代。
