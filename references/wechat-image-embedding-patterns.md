# WeChat 文章图片嵌入模式参考

> 图片**分类与删除**的实战协议（内容图/装饰图/引流图判定、连带悬空句与引流尾巴清理）见 `references/wechat-image-triage.md`。

## 通用模式

WeChat 文章图片在 runner 中以下载顺序排列（第 N 个下载对应第 N 张插图）。正文中可能有三种图注形式：

### 形式 A：显式编号图注
```
三者分层关系图图 1：MFS 是地基，Open Tag 是上层示例…*
```
特征：以中文短句 + `图 N：` 结尾的段落，尾部有 `*`。直接替换为 `![描述](图片)` + `*图注*`。

### 形式 B：孤立占位文字
```
GUI

微信里面对话
```
特征：HTML 转换后图注与正文分离为独立段落，无 "图" 字标识。常见于截图较多的教程。
匹配方式：扫描正文中短单词（CLI/GUI/截图/界面）或 `**第一步**`/`**第二步**` 前后的文本。

### 形式 C：无图注（仅示意性文字）
```
MFS 统一工作空间信息图封面封面：MFS 把 20+ 数据源统一成一棵可检索的文件树*
```
特征：段落以 `*` 结尾，内容是对图片的描述而非编号图注。直接替换，保留描述文本为斜体图注。

## 嵌入位置策略

| 文章类型 | 图片放置策略 |
|---------|-------------|
| 技术分析帖（含"图1""图2"） | 替换原编号图注行 |
| 教程帖（含"第一步""下载"等） | 放在步骤标题后、操作说明前 |
| 新闻/简短帖 | 放在相关功能段落（如"第一个：MCP"）标题后 |

## 本工作会话验证的模式

> ⚠️ 以下模式基于旧版「首图识别」经验，现已升级为**全量视觉筛查**。位置顺序不再可靠，必须对每张图调用 `vision_analyze` 判定类型后再决定保留或删除。详见 `references/wechat-image-triage.md`。

### MFS 类（5 张图）
第 1 张 → 待视觉筛查（可能是封面/内容图/引流图）
第 2 张 → 第一概念图（如三层关系）
第 3 张 → 架构图
第 4 张 → 切换/对比图
第 5 张 → 要素映射图

### 编程工具类（6 张图）
第 1 张 → 待视觉筛查（可能是封面/内容图/引流图）
第 2 张 → 代码架构/工具集
第 3 张 → CLI 命令行
第 4 张 → GUI 桌面界面
第 5-6 张 → 功能细节/系统示意

### 教程类（12 张图）
第 1-2 张 → 待视觉筛查（可能是封面/内容图/引流图）
第 3-4 张 → 论文/原理图
第 5-6 张 → 配置文件/终端
第 7-10 张 → 分步操作截图
第 11 张 → 结束/总结图
