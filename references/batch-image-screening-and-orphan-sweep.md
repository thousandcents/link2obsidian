# 批量图片视觉筛查 + 孤儿加粗终扫（2026-08-05 实战）

## 1. 用 delegate_task 批量做图片视觉筛查（替代主 agent 逐张 vision）

微信长文常带 20+ 张图。主 agent 用 `vision_analyze` 逐张判断会刷爆上下文窗口。
**改用 `delegate_task` 委托一个子 agent 批量筛查**，返回一个紧凑的判定表。

要点（实战验证，22 张全部成功）：
- 子 agent `toolsets` 传 `["vision", "file"]`（vision 让它能加载图片，file 让它能读路径）。
- context 里写清：用中文回复、每张图 `image_url` 传**绝对路径**、逐张调用 `vision_analyze` 不要遗漏。
- goal 里：列出全部图片的绝对路径 + 完整判定标准（封面/题图、引流图、二维码、装饰图、表情包、风险说明 → 删除；内容图/数据图表/架构图/示意图/历史照片 → 保留）+ 要求输出「文件名 → 类型（保留/删除）」紧凑表 + 汇总。
- 判定标准要逐字写进 goal，子 agent 无本会话上下文，看不到 SKILL.md。
- 返回后主 agent 只处理删除清单，验证「引用但缺文件 / 删除清单中文件是否被别文引用」即可。

## 2. 孤儿加粗终扫：postprocess 后删除所有未配对 `**`（安全兜底）

postprocess.py 已修复大量孤儿 `**` 模式，但**语义不可判定的残留仍会出现**（段首/段末孤立的 `**`）。
对剩余未配对的 `**`，与其猜测原文加粗范围（易引入错误强调），**不如直接删除**——恢复纯文本、
Obsidian 渲染干净、不破坏语义。加粗强调的损失可接受。

脚本（逐行统计，奇数个 `**` 即视为孤儿，删除该行孤立的那个）：
```python
import re
from pathlib import Path
p = Path(".../raw/articles/<文章>.md")
t = p.read_text(encoding="utf-8")
# 对每个已知孤儿位置做精确字符串替换删除对应的 `**`
fixes = [
    ("你还要他怎么样？**六个月连 iPhone", "你还要他怎么样？六个月连 iPhone"),  # 段首孤儿
    ("启动了需求**。", "启动了需求。"),                                            # 句末孤儿
    ("等于没改革**。", "等于没改革。"),
    ("四分之一完全不用**——", "四分之一完全不用——"),
]
for o, n in fixes:
    t = t.replace(o, n)
p.write_text(t, encoding="utf-8")
# 复检
bad = [l for l in t.split("\n") if "Clippings/images" not in l and l.count("**") % 2 != 0]
assert not bad, f"仍有孤儿加粗: {bad}"
```
注意：**不要**用「该行 `**` 为奇数就删光该行所有 `**`」的粗暴逻辑——会破坏该行已成对的加粗
（如实测行 `**- 三分之二...1.5 小时**；四分之一完全不用**` 有成对加粗 + 一个孤儿）。用精确
字符串替换逐个删孤儿，保留成对部分。

## 3. 表格数据缺失 → 标 N/A，正文文字分离（数据纪律）

微信转换中表格某单元格被压平成 prose（实测「电器普及率表」的 `冰箱` 行数据变成长句），
且原文数据不可考时：**不要虚构数值**。
- 表格行缺失数据填 `N/A`（`| **冰箱** | N/A | N/A | N/A | N/A | N/A |`）
- 被压平的 prose 提出来做成表格后的独立正文段（`**电气化本身并不创造需求**，电，...`）
- 与用户「所有数字须有来源，缺失标 N/A」的数据纪律一致。

## 4. 空标题 `###` 的兜底

微信转换常产生空标题行（单独的 `###`）。一次正则 `r"\n###\s*\n"` 删除即可。
注意：若上图紧邻（`![...](...)\n\n### \n\n### 实际标题`），一次精确替换可能因上一行图片引用
不匹配而静默跳过——直接上 `re.sub(r"\n###\s*\n", "\n", t)` 全量兜底，别用带上下文的 replace。
