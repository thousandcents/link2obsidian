# 代码块 Fence 合并陷阱

## 现象

postprocess.py 按语言标记（`rust` / `python` 等）在代码块间插换行，但**有时会将同一个逻辑代码块在多个语言标记处拆开**，产生多个独立 fence。

## 典型案例：iroh 文章 Rust 代码块

原文只有一个 Rust 代码块，包含连接方和接收方两段示例代码。postprocess 处理后变成两个独立 fence：

```markdown
```rust
// 连接方
...
```

// 接收方
...
```
```

需要手动合并为：

```markdown
```rust
// 连接方
...

// 接收方
...
```
```

## 触发条件

- 同一个代码块内有多个语言/章节分隔（如"连接方"和"接收方"两个代码示例在同一个 ```rust fence 内）
- postprocess 在第二处语言标记处额外插入了 fence 闭合+换行

## 修复方法

人工排查：在 postprocess 报告提示"需 AI 介入"后，检查相邻两个 fence 是否属于同一个逻辑代码块。若是，手动移除中间多余的空行和 fence 标记。

## 预防措施

postprocess.py 目前无法自动判定"同一个 fence 内的两个代码片段是否应该合并"，这是语义级问题，需要 Agent 人工判断。
