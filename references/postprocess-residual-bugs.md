# Postprocess 跑完后仍残留的 Markdown 缺陷

`postprocess.py` 覆盖了大量由正则/固定规则判定的清理，**但它跑完并输出"0 项需 AI"不代表文件已可发布**。以下缺陷是 postprocess 无法（也不应）用规则判定的语义型问题，需要在 postprocess 之后由 Agent 人工复核。

> 实战来源：2026-07-31 `散户如何在期货战场上打胜仗`（postprocess 报告 9 项自动修复、0 项需 AI，但 Agent 仍需手工修正 2 处）。

## 1. 标题 + 正文粘连（## 标题末尾直接跟正文，中间无空行）

**症状**：一条 `## N、` 或类似标题后直接跟正文，中间没有 `\n\n` 分隔。

```markdown
## 散户的八条作战方针知彼知己后，我们一起来制定作战方针。
```

**成因**：微信公众号 HTML 中某些标题和正文之间用 `<span>`/`<div>` 等块元素包裹，但块之间的换行在转换时被压平；postprocess 的「标题+正文粘连」规则覆盖的是 `## N. xxx。正文` 这种可明确判定的模式，但像 `## 散户的八条作战方针知彼知己后...` 这种正文紧贴在标题文本末尾的（标题本身不含句号的短标题 + 紧跟的导语），属于语义边界，postprocess 保守不动。

**修复**：人工识别标题语义边界，在标题与正文之间插入 `\n\n`。

```markdown
## 散户的八条作战方针

知彼知己后，我们一起来制定作战方针。
```

## 2. 内容跨段加粗 / 孤儿 `**` 的「段落级别闭合」盲区

**症状**：一行有 `**` 开头，后文有多行正文，但无对应行末闭合 `**`，导致整块内容（或首段）在 Obsidian 里被意外加粗，或者首行孤立 `**` 残留。

```markdown
所谓知彼知己，百战不殆。**我们一起看看双方的优劣势：

## 散户的劣势…
```

**成因**：原文 HTML 用一个跨越多个段落的 `<strong>`/`<b>` 包裹（或开头加了 `<strong>` 而结尾未配对的 div 内加粗），scraper 把 `<strong>` 转成 `**`，所以 markdown 里出现了"开了加粗但后面多段都跟着算加粗范围"的情况。postprocess 的「整段加粗丢失」规则**只在段末检测到 `**` 时才会补段首 `**`**，对于"段首有 `**` 但段末没有"的镜像情形不会反向修复——因为按段统计奇偶无法区分"这是段落级强调"还是"这行就是孤立残留"。

**修复**：人工判定。如果该 `**` 是跨段落的内容级强调（如「我们一起看看双方的优劣势」），建议整体删除多余 `**`（改成纯文本即可，不影响语义）；如果 `**` 只应包裹单个词，则补上闭合 `**`。

```markdown
# 改法 A（移除，适用于本案例）：
所谓知彼知己，百战不殆。我们一起看看双方的优劣势：

# 改法 B（若应保留加粗，则补闭合）：
所谓知彼知己，百战不殆。**我们一起看看双方的优劣势：**
```

## 3. 营销引流段落：删除引流图片时需检查是否应一并删除营销小节

**症状**：全文图片只剩一张二维码引流图，但该图片所在的小节本身是"加会员 / 扫码咨询 / 限时特价"类营销文案。

**判定**：当图片视觉分析确认是「引流图 / 二维码」后，Agent 除了删除图片引用和磁盘文件，还应检查该图片紧邻的段落是否也是同一营销小节的组成部分。若营销小节**独立成节**（有自己的 `##` 标题、价格、活动描述），**应连同营销小节一起删除**，不残留孤立的"限时特价 · 即将涨价"或"扫二维码"等无实质内容。

**本次实操**：文章第八节 `## 八、最重要的一条，加交易之道会员` 及后续"限时特价 / 扫二维码"整段一并删除。

## 4. 第 3 步（复杂 Markdown 修复）的「报告为 0 项需 AI」是乐观假设

postprocess.py 的 `⚠️ 需 AI` 输出是基于固定签名模式（如被压平表格、孤儿 `**` 等）的自动检测。当文件确实不包含任何被这些签名捕获的模式时，报告会显示"0 项需 AI"——但这**不等于没有残留问题**。

**操作纪律**：
1. 读取 postprocess 报告
2. **仍人工通读一遍 `.md` 文件**（重点看：第 3 步列出的语义型场景、图片前后段落、标题粘连、加粗闭合）
3. 修完后再通读确认

## 5. 删除营销内容后，检查文档末尾是否残留品牌/免责声明

有些文章在正文结束后保留"作者名 + 发布日期 + 免责声明"等模板化尾部（如"鲁班期号 · 王老师 · 2026年7月23日 / 期货有风险，投资需谨慎"）。这部分不是正文内容，可视情况保留或删除——删除后注意压缩尾部多余空行，避免文件以大量空白结尾。

## 6. 中文结标题 + 正文粘连（postprocess 漏捕）

**症状**：`# 结语`、`## 结语`、`# 总结` 等中文结尾标题，标题文本后直接粘连正文，无 `\n\n` 分隔。

```markdown
# 结语这一套 skill 真正值钱的是它的方法论：形成从性能测试数据……
```

**成因**：postprocess 的「标题+正文粘连」规则用正则匹配 `## N. xxx。正文` / `## N、xxx。正文` 这种「标题以编号+标点结尾」的模式。`# 结语` 这类中文结尾标题不包含编号或句号作锚点，因此命中不了该规则，会作为「标题+正文粘连」的漏网之鱼残留。**这是已知盲区。**

**修复**：人工在标题与正文之间插入 `\n\n`。

```markdown
# 结语

这一套 skill 真正值钱的是它的方法论……
```

**检测方法**：postprocess 跑完后，搜索正则 `^#{1,2}\s+[^#\n]{1,8}[^\n]{9,}$`（标题行长度异常偏长，通常 > 20 字），若发现疑似粘连，再人工核对语义边界。

**实战来源**：2026-08-02《如何用AI性能调优 Intel开源了一套skills》（postprocess 报告 11 项自动修复，漏掉「结语」粘连）。

## 7. 图片删除后残留孤立 `*`（markdown 格式残留）

**症状**：删除正文中的图片引用 `![](Clippings/images/xxx.png)` 后，图片所在的 markdown 行变为孤立的 `*`（原为图注斜体标记或图片后附带的斜体标记），残留在文档末尾。

```markdown
![xxx.png](Clippings/images/xxx.png)
*

# 结语
```

**成因**：微信文章中图片（尤其是结尾的引流互动图）通常紧跟一个斜体 `*` 标记（markdown 中的单 `*` 行是无效的强调/分隔符），postprocess 的图片路径修正规则只处理 `images/` → `Clippings/images/`，不处理图片删除后的残留字符。

**修复**：在删除图片引用行时，一并删除紧随其后的孤立 `*` 行。

**实战来源**：2026-08-02《如何用AI性能调优 Intel开源了一套skills》（删除引流图后残留 `*` 行，被后续手动清理捕获）。

## 8. 压平表格检测 → 假阳性（百分比/加粗的普通句子被误报）

**症状**：postprocess 报告 `⚠️ 需 AI：检测到 N 行疑似被压平的表格（含 % 与 ** 但无 | 分隔符），请按语义重建为 GFM pipe 表格`。

**检测签名（postprocess 自动触发条件）**：某行满足**所有**以下特征：
- 行内不含 `|`（无 pipe 分隔符）
- 长度 > 40 字符
- 含 ≥2 个 `%`（百分号）
- 存在 `**`（加粗残留）

**这是误报的经典触发模式**：量化/金融类文章中，正常句子常同时包含精度百分比（`10.4%`、`6.6%`、`22.1%`）和加粗强调（`**`），且句子本身长度 > 40 字。这类行**完全不是被压平的表格**，是 postprocess 基于结构特征的误报。

**实战案例**（2026-08-02，《量化团队如何用 Mamba 预测未来 100 步价格》）：
- postprocess 报告 1 项需 AI，列出 3 行「疑似压平表格」
- 经 Agent 逐一核查：3 行均为含百分比数据的普通句子，无任何表格语义
- **结论：全部误报，无需人工干预**

**操作纪律**：
1. 看到 `⚠️ 需 AI：疑似被压平的表格` 时，**不要先假设是表格**
2. 直接读取该行的上下文段落，判断是否存在表格语义（列对齐、表头行、数据对齐）
3. 若只是普通句子含百分比 → 忽略该提示，不需要任何修复
4. 若确为被压平的表格（语义上应是表格结构但 HTML 被压成 inline 文本）→ 按语义重建 GFM pipe 表格

## 9. 章节编号与中文标题直接粘连（无句号分隔）

**症状**：`## 126Q4依然过剩`、`## 227Q1是否反转`、`## 3没那么乐观` —— 阿拉伯数字章节编号（1/2/3）与中文标题文字之间**没有空格也没有句号**，编号和标题连成一个长单词。

**成因**：微信公众号 HTML 中章节标题的编号部分通常由 `<strong>1</strong>` 或单独 `<span>` 包裹，正文标题文本由另一个 `<span>` 包裹，两者之间仅靠 CSS margin 分隔。scraper 转换后 HTML 标签被剥离，编号与标题文字紧贴。postprocess 的「标题+正文粘连》规则用 `## N. xxx。正文` 和 `## N、xxx。正文` 匹配，**前提是标题末尾有句号或顿号**；纯中文标题无标点结尾的命中不了。

**修复**：将粘连的标题+章节编号拆分为三部分：`## <编号> <空格> <标题文本>`，并在标题后插 `\n\n` 与正文分隔。

```markdown
# 粘连前：
## 126Q4依然过剩我们还是利用新生仔猪数量去推测未来……

# 修复后：
## 1  26Q4 依然过剩

我们还是利用新生仔猪数量去推测未来……
```

**检测方法**：postprocess 跑完后，搜索正则 `^#{1,3}\s+\d+[^\s#\n]{2,}` 匹配标题行中数字后直接跟 2+ 个中文字符的模式；然后逐一人工核对语义边界拆分。

**实战来源**：2026-08-03《生猪，像极了那些年的橡胶！》（3 处 `## 126Q4`/`## 227Q1`/`## 3没那么乐观` 粘连）

## 10. 句末孤儿 `**` 残留（加粗末尾丢失开头）

**症状**：正常句末 `...多头熬不住只能割肉离场**。` / `...那怎么能去定性是不是反转呢**？` / `...总供给下降的幅度被大大抵消。**` —— 句子末尾带 `**。` / `**？` / `**`，但句首没有对应的 `**` 开头。这是跨段落 `<strong>` 标签开头丢失导致的孤儿闭合。

**成因**：微信 HTML 中整句加粗由 `<strong>` 包裹，但 scraper 有时把开头的 `<strong>` 吞掉（例如前面有 `<br>`、空 div 或其他标签导致正则不匹配），只留下句末的 `</strong>` → `**`。postprocess 的「整段加粗丢失」规则只在段**末**检测到 `**` 时补段**首** `**`，但像 `**。` 这种 `**` 紧跟标点符号的闭合残留，规则无法判断应该补开头还是删结尾。

**修复策略（优先级）**：
1. **优先删除**：若句子本身语义完整（如 "...只能割肉离场**。" 整句是自然的叙述句），直接删除末尾 `**。` 改为 `。`。这是最常见的情况——整句加粗本来只是强调，去掉不影响语义。
2. **补开头**：若确为需要强调的关键词短语（如 `**产能去化速度跟不上PSY**`），则补开头。
3. **整句包裹**：若该句子是整段强调的核心结论（如"...总供给下降的幅度被大大抵消。**"），补段首 `**` 变为 `**...总供给下降的幅度被大大抵消。**`。

**实战来源**：2026-08-03《生猪，像极了那些年的橡胶！》（5 处句末孤儿 `**`：2 处删除，2 处补开头，1 处整句包裹）

## 11. 正文末尾营销引流尾部（无 ## 标题的纯文字尾部）

**症状**：文章末尾残留 `欢迎扫码加入社群` / `关注公众号` / `加群获取报告` 等纯文字营销尾部，无独立 `##` 标题，紧跟在正文最后一节之后。

**成因**：这些尾部在微信原文中是页脚区（`<div class="we_chat_bottom">` 或类似容器），scraper 抽取时可能被包含在正文 div 范围内，postprocess 没有专门的营销尾部检测规则。

**修复**：在删除引流图片后，**检查文档末尾 3-5 行是否残留此类纯文字营销尾部**。若有，整体删除并压缩尾部多余空行。

## 12. 清理营销块后，`# 引言` 前仍有孤儿标题碎片残留

**症状**：删除知识星球广告块（`> 2026年重磅升级已全面落地！...`）和空 `## 参考` 后，`# 引言` 前面仍然残留：
- 标题副本碎片（`# 只盯着涨跌幅在裸奔？` 和 `用 Python 打造你的日内「可交易性」量化扫描器` 这两行）
- 另一篇引流文章标题（`用 Python 揭秘均值回归策略：你的收益从何而来？`）

**成因**：微信公众号原文正文 HTML 的正文 div 开头，常常把文章标题、公众号 logo 描述、以及另一篇文章的"推荐阅读"标题全部一起输出到正文里（这些内容在 OG meta 层已经作为 title 提取过）。runner 的 js_content 抽取捕获整段，scraper 把它们转成独立段落，postprocess 不识别这些是"孤儿碎片"。

**修复**：postprocess 后，**扫描 `# 引言` / `# 引言` 之前的所有非空行**，如果前一行或前几行是：
- 与 frontmatter `title:` 重复的标题（可能是带 `# ` 的副本）
- 纯引流标题（如"用 Python 揭秘..."）
- 空行和孤立图片引用

一律删除，保留从 `# 引言`（或第一个真正的正文标题）开始的干净正文。

**实战来源**：2026-08-05《只盯着涨跌幅在裸奔？用 Python 打造你的日内「可交易性」量化扫描器》——第一次删除广告块后，标题碎片和"用 Python 揭秘"引流标题仍残留，需第二次扫描清理。

## 13. 涉及图片行的批量替换：替换串不保留完整语法会静默丢弃 `(path)`（严重）

**症状**：批量编辑后图片引用变成裸 `![hash.png]`（无 `(Clippings/images/...)`），Obsidian 中图片静默消失；引用计数下降（实战：32 → 24）。

**实战事故**（2026-08-06 WorkBuddy 研报）：为在图片与 `###` 标题之间插空行，使用了

    re.sub(r"\]\(Clippings/images/[^)]+\)\n(### \d\.\d )", r"]\n\n\1", content)

匹配串含完整图片路径，替换串只保留了 `]` —— 一次损坏 8 张图片的路径，靠编辑后重数图片引用才发现。

**安全写法**：
1. 模式中对图片语法整体设捕获组，替换串原样回引：`r"(!\[[^\]]+\]\(Clippings/images/[^)]+\))\n(### )" → r"\1\n\n\2"`
2. 或干脆不让匹配包含图片部分——按标题行定位、在标题行前插空行。

**验证纪律**：对文章内容的任何批量替换后，立即重数图片引用：

    refs = re.findall(r'!\[[a-f0-9]{32}\.(?:png|jpg|jpeg)\]\(Clippings/images/', content)
    # 计数应等于编辑前数量（减去有意删除的图）

数量不符必有损坏，立即排查。

## 15. 代码 fence：独立成行的语言标记 + 缺失 closing fence（postprocess 只修 opening 的残留形态）

**症状**：代码块呈现为

    ```

    python
    # 注释
    git remote -v
    ...
    ls packages/
    这次探测的结果：

即 opening fence 存在，但语言标记 `python` 独立成行（前有空行），且代码体**无 closing fence**，后文正文（"这次探测的结果："）被吸入代码块。

**成因**：微信代码块常退化为行首语言标记；postprocess 的「fence 退化修复」处理部分行首模式后，可能留下这种 opening 已有但语言标记仍独立、closing 从未补上的形态（参见 SKILL.md「代码块 fence 仅修 opening 不修 closing」警告）。

**修复两件事**：
1. **合并语言标记进 opening fence，且按内容而非标记选语言**：标记经常是错的（实战：4 个块全标 `python`，实际内容是 shell 命令和 markdown 示例文档）。命令块（git/ls/cat）→ ```` ```bash ````；markdown/AGENTS.md 示例内容 → ```` ```markdown ````；不确定就留空。
2. **在后续正文前补 closing fence**：锚定代码最后一行 + 后续正文开头片段，`代码末行\n正文开头` → `代码末行\n```\n\n正文开头`。注意正文开头前的标点可能是 ASCII（见 §17）。

**验证**：修复后 `content.count("```")` 必须为偶数；按序扫描确认每个块在正文前闭合。

**实战来源**：2026-08-06《setup-matt-pocock-skills》（4 个代码块均为此形态，一轮修复补 4 个 closing fence + 修正 4 个语言标记）。

## 16. 行内代码中的尖括号占位符被 HTML 解析吞掉（`.scratch//` 现象）

**症状**：行内代码中的路径占位符变成双斜杠：表格/总结行里 `本地 markdown（.scratch//）`，而文章其它位置同一路径完整（`.scratch/<feature>/`）。

**成因**：原 HTML 中 `<feature>` 这类尖括号占位符被 scraper 的 `<[^>]+>` 抹平正则当作 HTML 标签整个删除。

**修复**：搜索文章其它位置的同一路径的完整写法（正文段落中通常保留完好，因为它出现在不同的代码/转义上下文中），用它回填表格/总结行的残缺处。检测信号：行内路径中出现反常的 `//`。

## 17. 字符串替换不匹配时：全角 vs ASCII 标点（先查 codepoint）

**症状**：`content.replace(old, new)` 报"未匹配"，但肉眼在文件里能看到这段文字。

**高频原因**：标点全角/ASCII 混用——scraper 或 postprocess 可能在某些位置产出 ASCII `.` `:` `()`，另一些位置是全角 `。` `：` `（）`。实战（2026-08-06）：fence 闭合替换用了 `docs/adr/`).\n到这一步`（全角 `。`），实际文本是 ASCII `.`，静默不匹配。

**排查方法**：读取实际行并打印 repr 查看精确字符：

    ln = content.split("\n")[194]
    print(repr(ln[-60:]))          # 看精确字符
    # 或 [hex(ord(c)) for c in seg]

**纪律**：替换不匹配时不要盲目多变体重试——先 repr 一次，照实际文本抄写 old_string。

## 18. 行内代码空格修复的两种安全写法（前导空格 + pangu 间距）

**前导空格修复带守卫**：`` ` CLAUDE.md` `` → `` `CLAUDE.md` ``。朴素懒匹配正则 `` r"` ([^`\n]+?)`" `` 有误伤陷阱：两个行内代码相邻且中间有空格时（`` `X` 时新建 `Y` ``），扫描可能从第一个代码的**闭合反引号**开始匹配，产生 `` ` 时新建 ` `` 这种跨代码误配——捕获了两个代码之间的正文文字并吞掉两侧边界反引号（实战命中 `` ` 时新建 ` ``）。

**守卫写法**（捕获组以空格开头/结尾的匹配跳过，迭代至稳定）：

    def guard(m):
        inner = m.group(1)
        if inner.endswith(" ") or inner.startswith(" "):
            return m.group(0)   # 疑似跨配对误伤，不动
        return "`" + inner + "`"
    pat = re.compile(r"` ([^`\n]+?)`")
    for _ in range(3):
        before = content
        content = pat.sub(guard, content)
        if content == before: break

**pangu 间距（CJK ↔ 反引号插空格）必须排除代码 fence**：全局插入会污染 fence 内的代码示例。按 ``` 切分内容，只对偶数索引段（代码外）应用替换：

    parts = content.split("```")
    CJK = r"[\u4e00-\u9fff\uff01-\uff5e「」（）：；，。？！]"
    def pangu(t):
        t = re.sub(r"`(" + CJK + r")", r"` \1", t)          # 闭合反引号后跟 CJK
        t = re.sub(r"(" + CJK + r")`(?=[^`\n])", r"\1 `", t) # CJK 后跟开反引号
        return t
    for i in range(0, len(parts), 2):
        parts[i] = pangu(parts[i])
    content = "```".join(parts)

**实战来源**：2026-08-06《setup-matt-pocock-skills》（朴素正则一轮只部分修复且引入误伤，换守卫迭代 + fence 分区 pangu 后才清理干净）。

## 19. 文末引用链接区两个变体：标题粘连条目 + 页脚引用块断裂

**变体 A：`### 引用链接` 标题与首条引用条目粘连**。微信文末脚注列表（`[1]`/`[2]` 参考链接）转换后标题与第一条粘在同一行，且 URL 被斜体包裹：

    ### 引用链接[1]awesome-llm-apps: *https://github.com/...*

    [2]Unwind AI: *https://www.theunwindai.com*

**修复**：标题后插 `\n\n`；条目编号后补空格（`[1] `）；去掉 URL 外侧 `*` 斜体（裸 URL 在 Obsidian 里自动链接，斜体反而干扰解析）。postprocess 的「标题+正文粘连」规则不覆盖 `标题[1]` 这种无标点锚点的粘连。

**变体 B：页脚引用块 `>` 与内容断裂 + 加粗偏移**。微信文末的 blockquote 卡片（如「🌟 仓库链接」）转换后引用符独立成行、内容落在下一行且 `**` 偏移：

    >
    🌟 仓库链接**：github.com/Shubhamsaboo/awesome-llm-apps[3]

**修复**：合并为一行并把 `**` 归位为成对加粗：`> 🌟 **仓库链接**：github.com/...[3]`。判定信号：独立的 `>` 空行 + 下一行行首无 `>` 但语义上是引用内容。

**实战来源**：2026-08-07《11.8 万 Star 的 LLM 应用库》（两变体同时出现，postprocess 报告 0 项需 AI）。
